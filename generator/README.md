# CMOP 合成数据生成器

语言归属见 [ADR 0004 的 2026-09-13 修订](../docs/dev/adr/0004-language-and-runtime-boundaries.md)，
规范见[合成数据生成规范](../docs/dev/requirements/data-generation-specification.md)。

## 当前范围：L-1 原型

只生成已冻结的最小订单生命周期 L-1（新建 → 接受 → 至少两笔部分成交 → 全部成交），
契约见[监管数据契约](../docs/dev/requirements/regulatory-data-contracts.md) §3.3 至 §3.6。
分配、结算、资金与公司行为段尚未接入。

```bash
uv venv --python 3.12 .venv && uv pip install --python .venv/bin/python -e 'generator[test]'
.venv/bin/cmop-generate-l1 --seed 20260913 --rows 1000000 --out /tmp/cmop-l1
.venv/bin/python -m pytest generator/tests
```

产出两件：`fix_l1_messages.parquet`，每行一条 FIX 报文；`manifest.json`，记录生成规范 §2 的
三项输入（种子、代码提交、参考数据抽取日期）与全表内容哈希。**产出不进仓库。**

## 已实现的契约

| 规则 | 出处 | 实现 |
|---|---|---|
| 子种子由根种子派生，不独立设置 | 生成规范 §2 | `SeedSequence.spawn`，子流顺序固定，只能末尾追加 |
| 派生字段计算、不采样 | §6.1 | `CumQty`、`LeavesQty`、`AvgPx`、`OrdStatus`、`ExecType` 全部由成交序列算出 |
| 五项分布参数 | §6.2 | 笔数 `3 + Geometric(2/3)` 截断 12；数量对数正态中位 500、σ 1.5、整手、5% 零股；逐笔切分末笔取余量；±10 bp 随机游走；指数间隔均值 45 秒 |
| 成交价与估值价同源 | §6.2 | 每标的一条日度价格序列，到达价取自该序列 |
| 标识符由种子决定 | §6.3 | 前缀取种子哈希，序号确定，不用 UUID |
| 上市前、退市后无事实 | §3 | 退市日取自钉住的 Form 25 索引 |
| 齐普夫 1.0 分配、5% 零事实、其余至少一单 | §6.6 | 秩次由种子置换，与代码顺序无关 |

`cmop_generator.verify_l1` 对产出逐条断言上述契约与 §3.6 三条不变量，测试在 20 万行上跑它，
并断言同种子逐字节相同、异种子不同。

## 原型的已知简化，均须在接入下一段前处理

1. **上市起始一律取窗口起点 2016-01-04。** 生成规范 §3 要求取首次申报日期，
   而钉住的参考数据里没有这一项。
2. **营业日只去掉周末，不去节假日。** 与 §6A.1、§6B.4 的营业日口径不一致。
3. **`TransactTime` 是交易所本地时间的朴素时间戳**，未带时区。
4. **买卖方向 50/50、订单类型一律市价**：两者规范未定，市价单使 `Price(44)` 条件不成立而不出现。
5. **不带 `Account(1)`**：账户维度（§3A）未接入。
6. **价格以整数美分存储**，`AvgPx` 为浮点；§3.6 注明价格精度等 schema 冻结。
7. **切分形状**：非末笔每笔取剩余可分配量的均匀份额，末笔形状与前几笔不同，§6.2 已要求承认这一点。

## 实测，2026-09-13，MacBook Pro 本机

| 量 | 值 |
|---|---|
| 行数 | 1,000,000 条报文，181,851 单 |
| 耗时 | 约 2.6 秒 |
| 峰值常驻内存 | 约 1.3 GB，**主要是 12505 × 2515 的日度价格矩阵** |
| Parquet 大小 | 33.5 MB，约 **33.5 字节／行**，pyarrow 默认压缩 |
| 重跑 | 同种子两次运行、Parquet 读回后内容哈希一致 |
| 分配形状 | 头部标的 18151 单，前十占 26.9%，有事实标的中位数 4 单 |

**价格矩阵随标的数乘营业日数线性增长，扩到目标规模前要改成按需计算。** 行宽与压缩率只对
L-1 这一种报文形状成立，不能直接替换工作负载基线里的规划假设。
