# CMOP 合成数据生成器

语言归属见 [ADR 0004 的 2026-09-13 修订](../docs/dev/adr/0004-language-and-runtime-boundaries.md)，
规范见[合成数据生成规范](../docs/dev/requirements/data-generation-specification.md)。

## 当前范围：L-1 订单生命周期接 A-1 分配

生成已冻结的 L-1（新建 → 接受 → 至少两笔部分成交 → 全部成交），并对每一单接 A-1
（J → P `AllocStatus=3` → P `AllocStatus=0`）。契约见
[监管数据契约](../docs/dev/requirements/regulatory-data-contracts.md) §3.3 至 §3.6、§3A.1、§3A.6、§3A.7。
**A-2、A-3、A-4 与确认段尚未接入**：当前每一单都走 A-1，§6B.2 的场景分布未生效。

```bash
uv venv --python 3.12 .venv && uv pip install --python .venv/bin/python -e 'generator[test]'
.venv/bin/cmop-generate-l1 --seed 20260913 --rows 1000000 --out /tmp/cmop-l1
.venv/bin/python -m pytest generator/tests
```

`--rows` 指 L-1 报文行数，分配段另加每单三行。产出不进仓库：

| 文件 | 内容 |
|---|---|
| `fix_l1_messages.parquet` | 每行一条 FIX 订单报文（D 或 8） |
| `fix_alloc_messages.parquet` | 每行一条 J 或 P |
| `fix_alloc_groups.parquet` | J 的 `NoAllocs` 重复组，每行一个账户 |
| `dim_account.parquet` | 账户维度 SCD Type 2 版本，含关闭与并户 |
| `instrument_daily_price.parquet` | 用到的（标的，营业日）价格点，与成交价同源 |
| `manifest.json` | 生成规范 §2 的三项输入与逐表内容哈希 |

## 已实现的契约

| 规则 | 出处 | 实现 |
|---|---|---|
| 子种子由根种子派生，不独立设置 | 生成规范 §2 | `SeedSequence.spawn`，子流顺序固定，只能末尾追加 |
| 营业日历 | §2A | 纽约证券交易所休市规则按年计算，含两天临时休市；结算周期按 T+3／T+2／T+1 三段 |
| 派生字段计算、不采样 | §6.1 | `CumQty`、`LeavesQty`、`AvgPx`、`OrdStatus`、`ExecType` 全部由成交序列算出 |
| 五项分布参数 | §6.2 | 笔数 `3 + Geometric(2/3)` 截断 12；数量对数正态中位 500、σ 1.5、整手、5% 零股；逐笔切分末笔取余量；±10 bp 随机游走；指数间隔均值 45 秒 |
| 成交价与估值价同源 | §6.2 | 每标的一条日度价格序列，**逐标的按需计算**，子流由标的下标派生 |
| 标识符由种子决定 | §6.3 | 前缀取种子哈希，序号确定，不用 UUID |
| 上市前、退市后无事实 | §3 | 退市日取自钉住的 Form 25 索引 |
| 齐普夫 1.0 分配、5% 零事实、其余至少一单 | §6.6 | 秩次由种子置换，与代码顺序无关 |
| 客户与账户两层、四类生命周期事件 | §3A.2 至 §3A.5 | 2000 客户；开立、关闭、改名、并户；并户只并入同客户、当日有效的账户，按日期升序处理故不成环 |
| A-1 逐步取值与逐账户参数 | 契约 §3A.6；生成规范 §6B.2a | N、客户选择、按剩余量切分、5 bp 佣金、买卖方向进入净额 |

`cmop_generator.verify_l1` 与 `verify_alloc` 对产出逐条断言上述契约、§3.6 三条不变量与
VA-1、VA-3、VA-4、VA-5，以及账户存续区间、版本首尾相接、并户目标合法。
测试在 20 万行上跑它们，断言五张表同种子逐字节相同、异种子不同，并用两条注入证明校验器会报错。

## 已知简化，均须在后续处理

1. **上市起始一律取窗口起点 2016-01-04。** 生成规范 §3 要求取首次申报日期，而钉住的参考数据里没有这一项。
2. **`TransactTime` 是交易所本地时间的朴素时间戳**，未带时区。
3. **买卖方向 50/50、订单类型一律市价**：两者规范未定，市价单使 `Price(44)` 条件不成立而不出现。
4. **订单报文不带 `Account(1)`**：账户在分配段才出现，符合买方分配流，但 `Account` 在 L-1 上是否要填未定。
5. **价格以整数美分存储**，`AvgPx` 为浮点；§3.6 注明价格精度等 schema 冻结。
6. **切分形状**：非末份取剩余可分配量的均匀份额，末份形状与前几份不同，§6.2 已要求承认这一点。
7. **实际 N 分布偏向 2**：采样权重是 40/30/20/10，实测为 57/31/9/2。原因是 N 被当日客户有效账户数截断，
   而每客户账户数均值只有 6、且 60% 的账户窗口开始后才开立。**要么在选客户时就按 N 过滤，
   要么接受并改写 §6B.2a**，未决。
8. **客户层不版本化**：§3A.2 要求客户也是 SCD Type 2，当前只有账户层。
9. **`<CommissionData>` 的 `CommType` 未落列**，佣金只以美分金额出现。

## 实测，2026-09-13，MacBook Pro 本机，种子 20260913

| 量 | 值 |
|---|---|
| L-1 | 1,000,000 条报文，181,851 单 |
| A-1 | 545,553 条报文，466,573 个账户组行 |
| 账户维度 | 12,066 个账户，13,452 个版本，3,259 个关闭，623 个并户 |
| 耗时 | 约 4.4 秒 |
| 峰值常驻内存 | 约 1.1 GB |
| Parquet 大小 | L-1 33.7 MB；A-1 报文 14.6 MB、组行 12.3 MB；账户 0.25 MB；价格点 0.76 MB |
| 重跑 | 两次运行五张表内容哈希一致 |

**价格矩阵改为按需计算后峰值内存只从 1.3 GB 降到 1.1 GB**，说明大头不在价格矩阵，
而在逐行拼接字符串标识符的 NumPy 字符数组。扩到目标规模前要改成分批写出。
行宽与压缩率只对这两种报文形状成立，不能直接替换工作负载基线里的规划假设。
