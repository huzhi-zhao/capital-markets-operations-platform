# ADR 0007: The External Interactive Path Reads Gold Only

> **Status**: Proposed · **Date**: 2026-09-12
>
> **Related architecture**: [平台架构](../platform-architecture.md) §5、§5.1、§6
>
> **Related requirement**: [工作负载基线](../workload-baseline.md) §3、§5.3、§5.7、
> [业务目标](../requirements/business-objectives.md) §3.1

## Context

CMOP 的数据在家庭局域网（NAS 与按需 MBP），对外交互路径在 OCI，两者之间隔着一条 WireGuard
隧道。**差异的解释链要不要穿过这条隧道**，是一个会同时影响 Gold 表设计、隧道流量、
演示可靠性与追溯性主张的问题。

[平台架构](../platform-architecture.md) §5.1 已于此前作出决定，**但该节自己写明"本节是访问
模式决定，尚未提升为 ADR"**，并留下条件：若后续 Gold 表设计因此产生独立的可逆取舍，
再评估是否单独立 ADR。

**那个条件已经成立。** 决定的后果之一是 Gold 里要出现一张明细粒度的异常解释表，
**而那是[工作负载基线](../workload-baseline.md) §3 一条规则的显式例外**，已挂号单独监控。
同时该决定已被四处引用：业务目标 §3.1 的主流程、roadmap、工作负载基线 §5.3 与 §5.7、
以及 [ADR 0003](0003-hybrid-deployment-topology-and-component-placement.md) 的隧道流量清单。
**一个被四处依赖、并已产生表设计例外的决定，符合 ADR 准入边界的第一条与第二条**，
因此本 ADR 把它从架构文档提上来。

**问题**：对外交互路径能读到哪一层，差异的解释链在什么时候算。

## Options considered

**一、交互路径可以跨隧道下钻 Silver。** 分析员点开一条差异，实时向 NAS 查它的明细来源。

**二、交互路径只读 Gold，解释链在夜间批次内物化。** 下钻降为局域网内的工程排查手段。

**三、把 Silver 也复制一份到 OCI。** 消灭跨隧道读取，代价是存储与同步。

## Decision

**采用选项二：对外能力不跨隧道。** 差异的解释链在夜间批次内计算并物化进 Gold，
**交互路径只读 Gold**。Silver 的逐笔下钻降为局域网内的工程排查手段，不进入对外演示范围。

**选项三不予采纳**：Silver 是 TB 级，复制它等于把"数据留在局域网"这条拓扑前提取消掉，
而那条前提是 [ADR 0003](0003-hybrid-deployment-topology-and-component-placement.md) 的基础。

理由四条，原样取自架构文档 §5.1：

1. **更接近真实运营。** 真实中后台的差异解释是批内预先算好的，
   **不是分析员每点一次就现场推一遍血缘**。
2. **把最脆弱的一环从演示主路径上摘掉。** Silver 在 NAS、Trino 在 OCI，
   穿隧道下钻的延迟比 Gold 查询高一个量级，**且依赖演示当时家里的隧道可用**。
3. **追溯性没有被削弱，反而增强。** 解释链与其他结果在同一批次算出、一起版本化、
   一起被重述，**因此可复现**。按点击实时推导的血缘做不到这一点。
4. **实时重算血缘在规模上本来就会炸。** 排除它是设计取舍，不是能力缺失。

**第三条是本决定唯一一条正面主张，其余三条都是避害。** 它也是最容易被误读成辩解的一条，
所以要说清判据：**可复现的定义是同一批次重跑得到同一条解释链**。
批内物化满足这个定义，实时推导不满足，**因为实时推导的输入是查询时刻的表状态**。

### 能力保留，但不作为对外能力使用

跨隧道读 Silver 的**能力保留在架构里**（[ADR 0003](0003-hybrid-deployment-topology-and-component-placement.md)
第 4 条允许带强谓词的下钻），**本 ADR 约束的是它算不算对外能力**。
两者的区别在验收：**对外能力要进演示主路径并被计时，工程排查手段不进**。

## Consequences

### Positive

- **演示主路径不依赖隧道可用性。** 这是四条理由里最实际的一条。
- **解释链与结果同批次、同版本、同重述**，追溯性主张有了可检验的定义。
- **NAS 不必安装 Trino。** 架构文档 §5 的这条结论直接来自本决定。

### Negative and risks

两条代价必须同时接受，**它们不是本决定的副作用，是它的价格**：

- **Gold 会出现一张明细粒度的异常解释表。** 这是[工作负载基线](../workload-baseline.md) §3
  "Gold 超预算先查是否混入明细粒度"那条规则的**显式例外**，**必须挂号并单独监控行数与
  字节数**。它的行数由异常条数而非事实条数决定，量级远小于事实表，**但增长率要单独盯**，
  因为异常条数在注入场景下不是稳定量。
- **解释链在批内无法确定时必须显式标记。** 例如原因事件尚未到达。
  该条异常标记为**"解释待补"，不得留空**。**空值会被读成"没有原因"**，
  与数据质量里 pass、fail、not evaluated 三分类同源，
  也与[验证与对账规范](../requirements/validation-and-reconciliation-specification.md)
  对 not evaluated 的处理一致。

### 本决定会在什么条件下被推翻

**写下来是为了让它可以被推翻，而不是只能被绕开。** 两个条件：

1. **若 BQ 层面出现一个必须交互式回到明细的问题**，且该问题不能靠预物化满足，
   则本决定与选项一之间要重新权衡。**目前 BQ-1 与 BQ-2 都不需要**。
2. **若隧道延迟被实测证明与本地 Gold 同量级**，理由二消失，剩下三条仍成立但强度下降。
   该实测属 W7，见工作负载基线 §5.7。
