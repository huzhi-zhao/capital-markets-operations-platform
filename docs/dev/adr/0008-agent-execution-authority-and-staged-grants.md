# ADR 0008: Agent Execution Authority and Staged Grants

> **Status**: Proposed · **Date**: 2026-09-14
>
> **Related ADR**: [ADR 0003 混合部署拓扑](0003-hybrid-deployment-topology-and-component-placement.md)
> 2026-09-09 修订、[ADR 0009 探测的声明式步骤与通用执行器](0009-probes-as-declared-steps-under-tools.md)
>
> **Related plan**: [在共享主机上启用 Iceberg](../design/2026-09-12-shared-host-iceberg-enablement.md)
>
> **执行状态**：**只定方案，未配置任何身份、凭据或放行名单。**

## Context

三件事同时成立，使"谁能在真机上执行命令"成为一个需要长期约束的问题。

**一、没有测试环境。** NAS、MBP 与 OCI 是 CMOP 唯一的一套环境，开发、探测与发布都落在上面。
任何一次执行都是对真实状态的执行。

**二、OCI 那台机器不是独占的。** [ADR 0003](0003-hybrid-deployment-topology-and-component-placement.md)
的 2026-09-09 修订决定复用兄弟项目 UOIP 的既有实例，并明确接受爆炸半径，
**但接受的是可用性风险，不是正确性风险**。共享的 Spark 容器与 Trino 本身就是 CMOP 以外的资源。

**三、执行权只在人手里，已经成为瓶颈。** 所有者报告，此前的探测需要人把代理写好的 SQL 与 CLI
逐条手工输入；下一阶段一轮 EDA 预计含几十至上百条 SQL、数百次 CLI，跨多台主机。
手工转录不仅慢，而且**不留执行记录**，与"数字必须附执行入口"的证据要求相冲突。

**问题**：代理可以在真机上执行哪几类动作，以什么身份执行，这些授权在什么条件下收回。

## Options considered

**一、只由人执行。** 现状。代理写命令，人复制执行。

**二、代理只做只读探测，所有写操作由人执行。**

**三、分阶段授权。** 探测长期授权；项目自有资源的发布在开发期授权，达到触发条件后收回；
共享资源的变更始终不授权。

**四、一开始就由流水线发布。** 代理只提交变更，发布一律由 CI 持部署凭据执行。

## Decision

**采用选项三。** 核心判据是：**授权的边界由身份强制，不由约定保证。**
身份做不到隔离的动作，一律不授权给代理。

### 一、执行动作分三类

| 类别 | 含义 | 开发期 | 收回后 |
|---|---|---|---|
| 探测 | 只读：读版本、容量、配置、本项目有权读的数据 | 代理直接执行 | 代理直接执行 |
| 项目内发布 | 只写 CMOP 自有的目录、schema、catalog、表与进程 | 代理直接执行 | 代理准备与 dry-run，人批准后执行 |
| 共享资源变更 | 写任何 CMOP 以外或与其他项目共享的资源 | **人工窗口** | **人工窗口** |

第三类的例子：UOIP 共享容器的镜像与重启、既有 Trino 的重启、宿主机系统配置、
创建或修改系统用户与权限本身。**它们不因任何阶段变化而授权给代理**，继续走
[shared-host design](../design/2026-09-12-shared-host-iceberg-enablement.md) 那样的择期窗口。

### 二、边界由身份强制

1. **专用身份。** 每个节点上为 CMOP 建立专用系统用户，无提权能力，写权限限于项目目录；
   数据库侧为 CMOP 建立专用角色，写权限限于项目自有 schema 与 catalog。
2. **CMOP 以外的数据一律只读**，任何阶段都不例外。
3. **代理不持有所有者的个人凭据。** 代理执行与人执行必须能从身份上区分。
4. **命名隔离。** CMOP 自有的容器、卷、网络与目录统一带项目前缀，使越界在清单上可见。
5. **身份做不到的隔离，动作降级到第三类。** 已知的一例：在共享主机上，**容器管理权限
   通常等价于宿主机 root**。在找到不等价的方案之前，OCI 上的容器操作属于共享资源变更。

### 三、只通过受控入口执行

代理只调用仓库中定义的执行入口，**不开放任意 shell、裸远程登录或数据库交互客户端**。
每个入口对应上表的一个类别，放行等级（允许、需确认、拒绝）按类别配置。
**放行名单本身的改动属于人工 review 范围**，代理不能自行放宽。

入口的具体形态见 [ADR 0009](0009-probes-as-declared-steps-under-tools.md)；
命令入口工具、远程执行工具不在本 ADR 选定。

### 四、项目内发布的前置条件

1. **发布前自动留存可回滚状态**：自有表的快照或备份、自有配置的上一版本。
2. **回滚入口与发布入口同时存在。** 没有回滚入口的发布，不授权给代理。
3. **每次执行留下记录**：执行入口、代码版本、目标节点、时间与结果。

### 五、收回条件与方式

**任一条件成立即收回项目内发布的授权**：

1. 出现依赖 CMOP 产出的真实用户或下游；
2. 开始执行不可重建的写入，例如全量回填；
3. 代理的一次执行影响了 CMOP 以外的资源。此时**立即收回**，并按
   [postmortem](../postmortem/README.md) 的准入条件判断是否复盘。

收回只改放行等级或改由流水线执行，**探测授权保持不变**。收回在本 ADR 追加带日期的修订。

### 为什么不选其他选项

- **选项一**：瓶颈与无记录两个问题都不解决。
- **选项二**：解决了探测，但开发期大量可回滚的自有发布仍要人手工执行，
  而此时既没有下游用户，也没有不可重建的数据，人工把关的收益最低。
- **选项四**：需要把流水线执行器放进家庭与云之间的内网，并单独管理部署凭据。
  在没有下游用户的阶段，成本高于收益。**它保留为收回后的去向之一。**

## Consequences

### Positive

- 一轮探测或一次自有发布不再需要人逐条转录，人的职责收敛为审结论和批准。
- 执行记录由入口自动留下，满足数字附执行入口的证据要求。
- 共享资源始终不在代理的权限内，UOIP 的可用性风险不因授权而扩大。

### Negative and risks

- **开发期的错误会直接落在唯一环境上。** 回滚入口是这项授权的价格，不是可选项。
- **建立专用身份本身是第三类动作**，必须由所有者在真机上执行。在那之前，本 ADR 的授权无法生效，
  代理只能继续提供命令由人执行。
- 放行名单是一份代理能读到的配置，**它的安全性依赖人工 review 真的看了这份配置的改动**。
- 容器管理权限的例外意味着 OCI 侧的大部分部署动作在开发期仍需人工，授权的实际收益
  主要落在探测与家庭侧。

### 本决定会在什么条件下被推翻

1. 若出现独立于生产的测试环境，"唯一环境"这条前提消失，发布授权可以放宽到测试环境、
   在生产收紧。
2. 若身份隔离在某个节点上被证明无法实现，该节点上的发布整体降级到第三类。

## Open questions

- OCI 共享主机上容器操作的隔离方案：rootless 容器运行时、独立守护进程，或维持人工。
- NAS 系统上专用用户与目录权限的实际能力。
- 执行记录的落点与保留期。
- 专用身份的建立是否并入 shared-host design 的无停机阶段一并执行。
