# 这个项目解决谁的什么问题

> **Status**: Draft · **Date**: 2026-09-14
>
> **用途**: 面向不熟悉资本市场后台的读者的入口，用日常语言讲清楚问题本身。
> 口径、数字、验收标准与 BO/BQ 编号的唯一事实源是[业务目标](business-objectives.md)
> 与[项目概览](project-overview.md)，本文只负责讲清问题，不重复定义。

## 1. 一句话

帮券商或银行后台的运营人员，在一个交易日的时间窗口内，从分散在多个系统的大量记录里
找出所有没对平的账，定位到具体是哪一笔交易的哪一个环节造成的，并在迟到数据和更正到来
时安全地重算历史、留下可审计的证据。

## 2. 主角的一天

主角是运营分析员，见[业务目标](business-objectives.md) §1.1。

早上到工位，前一天全公司成交了大量订单。每一单的生命周期是：下单、成交、分配到具体
客户账户、与对方确认、清算、交割。每一步都可能出岔子，而且**每一步的记录分散在不同
系统里**——自家交易系统、托管方发来的持仓对账单、清算所回的结算状态、银行发来的现金
流水。

他要回答的就是一句话：**昨天这一堆里，哪些没对平，为什么。**

典型的"没对平"是这样的：

- 自己账上写着卖出某数量，托管方对账单说实际出库的数量更少。
- 自己账上该收一笔现金，银行流水到账金额对不上。
- 清算所回执说这笔交割失败了。

**为什么急**：结算周期是 T+1，今天交易明天就要钱货两清，整个处置窗口只有一天。当天
下午之前查不清楚、改不过来，第二天就真的交割失败，要赔钱，也要计入上报的失败率。
T+1 的口径与它对时间窗口的影响见[业务目标](business-objectives.md) §4。

## 3. 为什么这件事难

难点不在于"算不出来"，在于三件事同时成立：

1. **量大。** 十年的交易生命周期事件，规模见[工作负载基线](../workload-baseline.md) §1。
   电子表格打不开，单机工具处理不完。
2. **不能抽样。** 抽查一批全对，不能证明剩下的对了。要回答"有没有未对平的记录"，
   只能全量比对。这条是主 BO 必须用大数据能力的根本原因，论证见
   [业务目标](business-objectives.md) §5.1。
3. **答案会变。** 查到一半发现某条是迟到的确认报文，那么前一天已经出的结果全部要
   重算；但又不能把无关的数据一起搞乱，还得留下改之前和改之后两个版本。

## 4. 平台给他什么

对应的 BQ 编号见[业务目标](business-objectives.md) §3。

**一、到岗时队列已经在那了。** 夜里批次跑完，异常清单已生成，按涉及金额和离结算截止
时点的远近排好序。他不用自己找问题，从第一条开始处理即可（BQ-1）。

**二、点开任何一条，能看到是哪个环节出的事。** 这是最值钱的能力。不是告诉他"差了多少"，
而是给出一条事件链：在哪下的单、成交了哪几笔、分配到哪几个账户、哪一条确认没回来或
数字不符、结算指令卡在哪；**每一环带上它对这个差额贡献了多少，加起来等于差额总数**
（BQ-2，也是代表性 BQ）。

**三、迟到数据来了只重算受影响的部分，新旧两版都留着。** 下午对方补发了漏掉的确认，
平台自动重算涉及的持仓、成本与报表，不碰无关数据，并保留前后两个版本，以便回答
"你昨天报的数怎么变了"（BQ-3）。

**四、公司行为能倒着重算。** 某只证券做了拆股或反向合股，历史上的持仓与成本基础都要
跟着改。平台要能改完，并证明只改了该改的（BQ-5）。

**五、不只事后查，还能事前提醒。** 批次结束时先给出哪几条最可能真的失败或延迟，差异
原因先自动归类，由分析员确认；已物化的解释链还能转成可读摘要（BQ-7、BQ-8，属 BO-4，
边界见[业务目标](business-objectives.md) §2.3）。

## 5. 另外两类人

- **运营主管**：不看单条，看聚合——差异集中在哪个对手方、哪个业务域，趋势是否恶化。
- **合规与审计**：偶尔触发，问"某个历史结论当时依据什么"，要求连同当时的规则版本与
  数据版本一起复现。

## 6. 用户少不等于价值低

这一节只解释项目定位，不涉及就业市场判断，后者不属于本仓库，见
[Requirements 索引](README.md)的边界说明。

面向消费者的系统，价值大致随用户数和使用频次增长。这套系统不是：一个运营部门可能只有
很少的人在用，但他们经手的是全公司的交割，**单笔出错的代价是罚息、赔偿与监管处罚**。
用户少是因为这件事只有专业人员做得了，不是因为它不重要。

另外两条特征同样与消费级系统不同：

- **它是强制的，不是可选的。** 监管要求机构能证明账是平的，这项能力不会因为业务优先级
  变化被裁掉。
- **全行业做法相似。** 每一家券商、托管行、清算机构、资管公司后台都在做同一件事，而且
  报文标准是全球统一的公开规范。因此这里建立的领域模型不是一家一套的私有逻辑。
