> **Status**: Draft · **Date**: 2026-09-09
>
> **Decision state**: 本清单按 §2.1 的暂定主 BO（BO-1 交易生命周期对账与差异归因）推导。
> 主 BO 排序变更时本文必须重新推导，不得沿用。
>

## 1. 分类原则

Bronze 落的是**来源对齐**的原始事件，不是已经统一口径的结果。对账要在生命周期各环节
之间定位断点，因此每个环节必须是独立的 Bronze 源；合并成单一"交易流水"表会让差异无从
比对。

数据按获取方式分三种，文档中必须始终可区分：

| 标记 | 含义 |
|---|---|
| 合成 | 由生成器按契约产出 |
| 真实 | 公开可获取的真实数据 |
| 推导 | 由其他层计算得出，不独立采集 |

明确标注哪些是合成、哪些是真实，是可信度要求，不是可选说明。

## 2. 源清单

### 2.1 交易生命周期事件（合成）

| 源 | 报文标准 | 到达方式 | 规模 |
|---|---|---|---|
| 订单事件，含新建、撤单、改单 | FIX | 批量生成落 Bronze | 五项合计 400–700 GB |
| 成交回报 | FIX | 同上 | |
| 分配指令 | FIX | 同上 | |
| 结算指令与状态 | ISO 20022 `sese` 族 | 同上 | |
| 资金流水 | ISO 20022 `camt` 与 `pacs` 族 | 同上 | |

真实订单与成交数据是券商私有资产，不存在公开来源，因此事实全部合成；但**格式是公开
的**，FIX 规范与 ISO 20022 报文定义均可免费获取。具体报文标识符在 `regulatory-data-
contracts.md` 完成规范阅读后确定，当前只锁定报文族。

预期历史：十年。

质量风险：报文字段覆盖不足、代码表取值不合规、生命周期状态机出现非法跃迁。

敏感度：无，全部合成。

### 2.2 对手方对账单（合成）

| 源 | 对应内部账本 |
|---|---|
| 托管方持仓对账单 | 持仓快照 |
| 清算所结算状态回执 | 结算指令与状态 |
| 银行现金对账单 | 资金流水 |

**这是对账能否成立的前提，也是早期草案中缺失的一类。** 对账需要两个独立来源，对手方
一侧必须独立生成，不得由内部账本推导，否则永远对得平，主 BO 失去意义。

差异必须在生成阶段按设计比例注入，且可区分为四类：时间差、口径差、真实错误、正常在途。
能否自动区分这四类，是 BO-1 的核心验收点。具体比例进入
`data-generation-specification.md`。

### 2.3 状态快照（推导）

每日持仓快照，100–200 GB，由成交累加得出。单独落层，因为时点重建与重述都以它为基准。

质量风险：与成交累加结果不一致，即业务不变量被破坏。这是必须自动断言的项。

### 2.4 真实维度与参考数据（真实）

| 源 | 可获取渠道 | 规模 |
|---|---|---|
| 汇率、利率曲线（加拿大） | 加拿大央行 Valet API，免费官方，含历史。**已验证可用**，见 §5.1 | 小于 1 GB |
| 汇率（欧元区口径交叉验证） | ECB 参考汇率，经 Frankfurter 无 key 访问。**已验证可用**，见 §5.1 | 极小 |
| 公司行为：拆股、合股 | SEC XBRL frames API，按季度一次调用取回全部申报人。**已验证可用**，见 §5.3 | 数 MB |
| 公司行为：分红 | 同上，`CommonStockDividendsPerShareDeclared` | 数十 MB |
| 公司行为：更名 | SEC `submissions` 接口的 `formerNames`，带起止日期 | 数 MB |
| 公司行为：退市 | SEC 季度 `form.idx` 中的 Form 25 / 25-NSE | 数 MB |
| 证券主数据：代码、CIK、交易所 | SEC `company_tickers_exchange.json` | 小于 1 MB |
| 法人实体主数据、合并状态 | GLEIF Global LEI Index，CC0 | 数百 MB |
| 日线行情 | **不采用真实数据**，转为合成，理由见 §5.4 | 1–3 GB |

价值不在体量而在**脏**：退市、拆股、代码变更、缺失值正是数据质量框架的处理对象。公司
行为同时是 BO-3 重述能力的全部输入。

证券主数据与公司行为一度被判定为无法闭合。2026-09-09 的第二轮取证推翻了这个结论：
SEC 的结构化接口同时满足十年历史、免费、允许再分发三个条件，已定为公司行为主源，
见 §5.3。

敏感度：公开数据，需记录各来源的使用条款。SEC 要求请求头声明 User-Agent 并附联系
邮箱，且每秒不超过 10 次请求；接入前必须填入真实联系方式。

### 2.5 规则与契约（真实，非数据）

FINTRAC 报告规格与门槛、CIRO 报送要求、FIX 标签表、ISO 20022 报文目录。

它们不是数据集而是契约，必须版本化进入仓库。即便 BO-2 已降级，"每个结果可追溯到当时
生效的规则版本"这一要求依然成立，因此规则版本本身就是被引用的对象。

## 3. 到达方式

全部走批量生成直接落 Bronze。Kafka 只承载演示与回放窗口，不承载历史生成。

这条与 [平台架构](../platform-architecture.md) §7 的批次可重跑约束绑定：不采用依赖
"昨天那一趟已经跑过"的状态式增量设计。

## 4. 阶段与可舍弃项

| 源 | 阶段 |
|---|---|
| SEC EDGAR XBRL | 最后阶段，时间不足时整体舍弃 |

XBRL 不服务于交易生命周期对账，其半结构化解析价值已由 FIX 与 ISO 20022 覆盖。它不得
进入任何前置阶段的依赖链。

## 5. 取证记录

> 探测日期 2026-09-09。方法为直接调用公开端点并检查返回内容与许可条款。
> 结论可被后续重测推翻，重测时更新本节并记录新日期。

### 5.1 已验证可用

**加拿大央行 Valet API**：无需 API key，目录含 15,922 个序列。汇率与国债收益率两类均
返回正常数据。

| 序列 | 覆盖 |
|---|---|
| `FXUSDCAD` | 起始 2017-01-03。2014 年区间返回空 |
| `IEXE0101`（legacy noon rate） | 覆盖 2017 年之前，2014 年区间正常返回 |
| `BD.CDN.{2,3,5,7,10}YR.DQ.YLD`、`BD.CDN.LONG.DQ.YLD`、`BD.CDN.RRB.DQ.YLD` | 正常返回 |

许可条款：允许自由使用、复制与分发，条件是标注央行为来源并说明是否做过修改；若以付费
形式提供含该内容的材料，须事先告知对方该材料在官网免费可得；不得绕过请求频率限制。
央行未采用 Creative Commons 之类的正式开放许可，而是自定的附条件许可。

**ECB 参考汇率（经 Frankfurter，无需 key）**：`2014-06-06..2014-06-20` 区间返回正常。
作用是给加拿大央行口径提供一个独立的交叉验证源。两个官方口径对同一天的同一货币对给出
不同数值，这本身就是对账差异分类里"口径性差异"的天然样本。

**十年汇率必须拼接两个序列**，因为 2017 年央行更改了汇率发布方法。这个断点不是障碍，
是**真实的参考数据不连续案例**：口径变更、序列替换、拼接边界的重复与缺口，正是数据质量
框架要处理的对象。建议主动保留它，不要用单一序列绕过去。

### 5.2 已验证不可依赖（商业行情渠道）

| 渠道 | 探测结果 |
|---|---|
| Yahoo Finance 端点 | 本机网络返回 HTTP 429；现需 cookie 与 crumb 才能访问 |
| Stooq CSV | 返回 JavaScript 人机校验页，非数据 |

许可层面同样不成立：Yahoo 的条款限于个人非商业用途，且其行情来自交易所与供应商授权，
再分发受底层许可约束。本项目是公开作品集，不能建立在这类来源上。

商业公司行为供应商同样排除。免费档普遍限制历史深度，允许免费取用的通常禁止对外再分发；
少数宣称"免费再分发"的授权只覆盖其特定行情订阅，不覆盖公司行为产品。**结论是不要在
商业供应商这条路上继续找**，官方与监管来源才是出路，见 §5.3。

### 5.3 公司行为：SEC 结构化接口是最优解

第一轮取证的结论"没有免费且可再分发的十年数据源"**已被推翻**。它只对商业行情供应商
成立，对美国证监会不成立。

**许可依据。** SEC 在其隐私与网站政策中明确写明，站上信息属于公开信息，用户无需 SEC
许可即可复制或进一步分发，只需注意不得使用其徽标与商标，并建议注明来源。这是商业供应
商不会给出的授权。所提取的内容本身也只是事实（某标的、某日、某比例），不是受保护的
表达。

**已实测的覆盖面。** 探测日期 2026-09-09，全部为直接调用后检查返回内容：

| 事件类型 | 接口 | 实测结果 |
|---|---|---|
| 拆股与合股 | `api/xbrl/frames/us-gaap/StockholdersEquityNoteStockSplitConversionRatio1/pure/{CYyyyyQnI}.json` | CY2014Q2I 返回 65 家、CY2020Q3I 61 家、CY2022Q3I 45 家 |
| 分红 | `api/xbrl/frames/us-gaap/CommonStockDividendsPerShareDeclared/USD-per-shares/{CYyyyyQn}.json` | CY2019Q1 返回 1217 家 |
| 更名 | `submissions/CIK{10位}.json` 的 `formerNames` | 返回带 `from`/`to` 的历史名称区间 |
| 退市 | `Archives/edgar/full-index/{yyyy}/QTR{n}/form.idx` 中 Form 25 与 25-NSE | 2018 Q1 有 318 条 |
| 代码与交易所全集 | `files/company_tickers_exchange.json` | 单文件约 522 KB |

**为什么 frames 接口是关键。** 它按会计期间横向切片，一次调用返回该期间内所有申报人
的同一个事实，而不是按公司逐个抓取。十年 40 个季度 × 2 个概念约 80 次调用即可覆盖，
总量数十 MB。

**这不是把已否决的 XBRL 决定翻回来。** 被降级并允许整体舍弃的是"批量解析二十到五十 GB
财报 XBRL 作为一类工作负载"。此处用的是针对性接口调用，体量小三个数量级，角色是维度
与参考数据，不是 Bronze 事实。两者不冲突，[容量基线](../data-volume-baseline.md) §1 已
分别列出。

**必须承认的局限，它们本身是项目素材。**

1. 覆盖面来自**申报人自报**，不是交易所权威公告。公司未标注该概念就不会出现。因此得到
   的是真实事件的**样本**，不是完备的公司行为馈送。文档与面试口径都必须这样表述。
2. `StockholdersEquityNoteStockSplitConversionRatio1` 混装正向拆股与反向合股，实测比例
   从 0.002 到 7 不等，其中个别值疑似不是拆股比例而是其他换股比率。**必须写校验规则**
   区分，这正是数据质量框架要处理的对象。
3. 记录上的日期是申报所报的时点，可能是分派日、记录日或期末，语义随申报人而异。需要
   逐类核对并在生成规范中固定口径。
4. 反向合股在样本中确实存在，而它是重述里最难的一类。这一点对 BO-3 是加分。

**结论：采纳 SEC 结构化接口为公司行为主源，GLEIF 作为法人实体与合并状态的补充源（CC0
许可）。** §5.3 原先提出的"手工整理真实事件清单"方案作废，不再需要。生成器仍按合成
标的产出明细，但事件的类型、日期分布与比例分布以真实抽取结果为锚。

### 5.4 日线行情：决定不采用真实数据

这一项不是找不到，是**不该找**。

Bronze 的标的是合成的。给合成标的配真实价格没有意义：价格对不上标的，反而在数据里制造
一层假的对应关系。真实价格只有在使用真实标的时才必要，而使用真实标的会把行情许可问题
重新引进来。

因此行情维度表转为合成，并在数据生成规范中明确标注为合成。真实性由另外两处承担：

- **汇率与利率曲线用真实数据**，因为它们是市场环境而不是标的属性，可以正确地套在合成
  组合上。来源为加拿大央行 Valet 与 ECB 参考汇率。
- **公司行为的事件形态用真实数据**，见 §5.3。

BO-1 的对账和 BO-3 的重述都不需要市价。持仓重述改的是数量与成本基础，不是市值。这条
判断使行情源从阻塞项降为非阻塞项。

### 5.5 抽取范围与拆股比例校验规则

**抽取范围：取满十年 40 个季度全量，不先做子集。** frames 接口按期间横向切片，40 个季度
两个概念合计约 80 次调用、数十 MB，成本低于为验证管道另写一套子集逻辑。子集只能证明管道
跑得通，证明不了跨期间的口径漂移，而口径漂移正是这批数据最需要暴露的问题。

**拆股比例的校验规则采用参考数据领域的通行做法。** 五条，顺序不能调换：

1. **先按上下文排除，再看数值。** 同一个概念合法地承载非拆股的换股比率，包括优先股转
   普通股、SPAC 单位拆分与并购换股比例。这些事实带有不同的 XBRL 维度成员，所属表单类型
   也不同。先按上下文与表单类型过滤，再进入数值判断。顺序反过来会把真实拆股当异常丢掉。
2. **归一到单一约定。** 只存一个数：调整因子 F = 事件后股数 / 事件前股数。二比一正向拆股
   F 为 2，一比十反向合股 F 为 0.1。下游只有一个公式，数量乘 F、成本基础除以 F。不存
   `2:1` 这类文本，也不设独立的方向标志位，因为标志位会与数值互相矛盾。
3. **不采信单一字段，用独立观测交叉验证。** 比例字段本身有歧义，申报人可能报分子也可能报
   分母，同一个 `10` 既可能是正向也可能是反向。独立证据是事件前后的流通股数，取自
   `dei:EntityCommonStockSharesOutstanding`。股数翻倍即为正向拆股，与字段里写的是 2 还是
   0.5 无关。两个证据不一致时以股数为准，并记录该分歧。
4. **合理区间只做告警，不做过滤。** 正向拆股实际集中在 1.5、2、3、4、5、10，反向合股集中
   在二分之一到百分之一。落在区间外的记录进入告警，但不自动拒绝，罕见的合法取值确实存在。
5. **判定结果必须是三分类。** 通过、拒绝、待裁决，不是通过与拒绝两分类。待裁决记录保留
   原值与原因码并计入统计。静默丢弃会破坏完整性度量，静默接受会污染下游重述。

第五条是这条规则对本项目的真正价值：它是一个**外生的**脏数据案例，不是为演示数据质量而
人为注入的。待裁决计数直接成为数据质量框架里的完整性指标。

### 5.6 真实事件到合成标的的绑定

**决定采用一对一别名绑定，不采用只取分布特征的方案。**

缺口在于：账上的标的是生成的，而公司行为是真实公司身上发生的事，两者之间必须有一座桥。
绑定方案给每个真实申报人配一个稳定的合成别名，该申报人的真实事件序列原样落到对应的合成
标的上，事件类型、日期、比例与先后顺序全部保留。

**选它的理由是时间相关性白送。** 真实的公司行为日历是成块的：分红扎堆在宣派季，反向合股
扎堆在市场低迷期，退市常跟在反向合股之后数月。这种成块与跨事件相关性正是压批处理管道的
东西。走分布特征就必须把这些相关性逐条显式建模，是额外工作量，且建出来的仍是假设。绑定
还能保证数据里一定存在"反向合股后退市"这类最难的序列，而抽样只能碰运气。

**副产物是标的宇宙的规模自己定了。** 十年窗口内约一万家申报人，对应约一万个合成标的。按
目标成交量摊平，每个标的每个交易日几十到两百笔，这个密度本身合理，不需要再单独假设。

**别名映射表的约定。** 它是参考数据，不是事实数据：

| 列 | 含义 |
|---|---|
| `synthetic_instrument_id` | 生成器的稳定标的主键 |
| `synthetic_ticker` / `synthetic_name` | 生成值，与真实名称无任何派生关系 |
| `source_cik` | 被绑定的真实申报人 |
| `listed_from` / `delisted_on` | 取自该申报人的首次申报与 Form 25，构成标的生命周期 |
| `binding_seed` | 生成该映射所用的随机种子 |

四条规则：

1. **一对一，不复用。** 一个 CIK 只绑一个合成标的，反之亦然。
2. **映射一次生成后作为参考数据固化，不随每次运行重算。** 否则重跑会得到不同的标的集合，
   所有跨运行比较与幂等性验证同时失效。
3. **真实标识符只存在于本表。** `source_cik` 不得出现在 Bronze、Silver 或 Gold 的任何列中，
   否则"事实全部合成"这个口径就不再干净。跨过去的只有事件本身：类型、日期、比例、金额。
4. **真实名称与代码一律不带入。** 更名事件带过来的是"某日发生过一次更名"，新名字由生成器
   产出。

**已知局限，与 §5.3 第 1 条同源。** 抽取到的是自报样本而非完备馈送，因此某个合成标的可能
缺少它对应的真实公司实际发生过的事件。这不影响数据内部自洽，口径始终是"事件形态锚定真实
观测"，不是"完整的公司行为馈送"。

别名可以用事件日期反推还原。此处无所谓，源数据本就公开，映射表也不含任何非公开信息。

## 6. 未决项

- 各源的 Bronze 分区键与批次标识约定。
- 对手方对账单的差异注入比例。
- 各源保留期限与 snapshot 过期策略的对应关系。
