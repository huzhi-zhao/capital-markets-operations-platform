# Roadmap

> **Status**: Draft · **Date**: 2026-09-02
>
> 本文表达能力阶段与退出条件，不跟踪每日任务状态。

## Phase 0: 决策与契约，2026

2026 年不实现生成器，不搭建管道组件。**2026-09-09 起为一次性 probe 开了一个有界例外**，
见下方"probe 例外"。阶段交付只有：

1. 确定主 BO、支持性 BO、BQ 与可验证的成功标准。
2. 阅读并引用公开监管与行业规范，形成最小数据契约和《数据生成规范》草案。
3. 写出业务不变量、对账口径、异常注入和验收门禁组成的验证规范。
4. 将项目边界、分层和部署拓扑 ADR 从 Proposed 推进到足以指导开发的状态。

退出条件：主 BO 已明确；MVP schema 可从 BO 反推；生成器输出与验证规则都有书面契约；
前三篇 ADR 的开放项不存在会推翻整个实现方向的阻塞问题。

### Probe 例外

**为什么开这个口子。** 原边界的目的是防止项目在没有 BO 和契约的情况下滑进堆组件，那个风险
今天已经不存在：BO 假设已检验，公司行为已实测，L-1 已冻结。而边界本身开始产生反效果——
[技术选型评估要求](requirements/technology-selection-evaluation.md) §7.1 的纸面筛已经证明
24 GB 的默认组合装不下，**下一步的答案只能来自部署后的实测，资料里没有**。继续维持边界等于
让一个已知错误的容量假设留在架构文档里过冬。

**例外的范围，四条都成立才算落在例外内**：

1. 只为回答一个已写进章程的 probe 问题，章程含风险、输入、阈值与停止条件；
2. 一次性、可丢弃，用完即拆，不留作 Phase 1 的部署基线；
3. 不实现生成器，不建任何 Bronze/Silver/Gold 表，不产生业务数据；
4. 结论写回 requirement、容量基线或 Proposed ADR，测量值附版本、配置、节点与日期。

**没有放宽的部分。** 生成器仍不实现，管道仍不搭建，全量回填仍必须在 BO baseline 冻结之后。
[立项与就绪度](project-inception-and-readiness.md) §5 的六条 probe 边界继续全部适用，本例外
只是解除"2026 年内一律不部署"这一条时间限制。

## Phase 1: 小规模端到端验证，2027

- 实现参数化生成器原型，先产生约 100 万行可复现数据。
- 跑通 Bronze → Silver → Gold 最小链路。
- 验证业务不变量、幂等重跑、一次迟到确认和一次更正或撤单。
- 验证 Spark、Iceberg、Catalog、Trino 与对象存储的真实兼容性。
- 测量 bytes/row、压缩比、文件数、shuffle、运行时间和资源峰值。

退出条件：小规模数据能回答主 BO 的最小 BQ；所有验收命令可以重复执行；容量模型已经由
实测替代主要猜测。

## Phase 2: 扩展到目标规模，2027

- 将事实数据扩展到 800 GB–1.5 TB。
- 落实分区演进、compaction、snapshot 生命周期和失败恢复。
- 实现迟到数据的受影响范围重算，不依赖全量摄取。
- 建立对账、数据质量、血缘和 Gold 认证。
- 构建 BO-4 的特征表，并把时点正确性断言纳入质量门禁：特征不得包含预测时点之后的信息。
- 验证 Silver 宽扫描与定点下钻的两条执行路径，均为局域网内的工程能力；对外路径只读
  Gold，见[平台架构](platform-architecture.md) §5.1。

退出条件：错误分区或文件策略会产生可观察差异；目标规模能够完成关键批次；重跑、重述、
对账和追溯都有实际结果，而不是只存在于架构图中。

## Phase 3: 运营化与作品交付，2028

- 完成公司行为历史重述、监管窗口、风险聚合等支持性场景。
- 跑通 BO-4 的建模段：模型训练、批量推理、结果回写并纳入既有血缘与版本控制。
- 建立面向运营场景的可视化与自然语言交互，只读已物化结果。
- 建立稳定演示数据集、Dashboard、运行手册和故障演练。
- 用 launch record 保存关键回填与规模化执行证据。
- 对达到触发条件的真实故障完成 postmortem，并把改进反馈进门禁和 ADR。
- 整理公开 guide、架构叙事和可复算的性能数据。
- 在托管平台上做一次对照验证，见下方"托管平台对照验证"。

退出条件：新读者可以从项目入口理解业务问题、运行最小演示、查看实际数据工程证据，
并沿文档追溯关键架构取舍。

### 托管平台对照验证

**目的是对照，不是迁移。** 本项目的全部取舍都建立在自建之上：引擎、catalog、分区与文件
治理、执行端划分。托管平台会把其中一批决策变成平台默认值，**那正是可对照的地方**。因此这
一项的产出是三份材料，不是一套并行系统：

1. 一个完整垂直切片在两边各跑一次，Bronze 到 Gold，含一次迟到确认与一次重述。
2. 同一批数据的可比指标：墙钟时间、资源消耗与折算成本，口径与
   [工作负载基线](workload-baseline.md) §4 一致。
3. **平台替本项目做掉了哪些决策**，逐条对照已有 ADR 的被否方案。

**不搬全量。** 目标规模的价值在于压出分区、小文件与重跑成本，那已在 Phase 2 压过；把同一批
字节再传一次不产生新结论，且家庭上行带宽本身还是未实测项，见工作负载基线 §4。

**表格式不需要重建。** 托管侧对 Apache Iceberg 提供元数据虚拟化：外部 Iceberg 表可被平台
各引擎当作 Delta Lake 读取，无需手工转换。因此这一项是"接上去"，不是"照着重写一遍"，
本项目的开放表格式选择在这里第一次产生可验证的收益。检索日期 2026-09-15，来源
[OneLake Iceberg tables](https://learn.microsoft.com/en-us/fabric/onelake/onelake-iceberg-tables)。

**时序是硬约束，且不可逆：**

- 试用容量为期 60 天，**一次性，不可续期**，到期须转付费容量。来源
  [Fabric trial capacity](https://learn.microsoft.com/en-us/fabric/fundamentals/fabric-trial)。
- 试用注册要求工作或学校账号，个人邮箱不受理；免费开发者 sandbox 已收紧资格，来源
  [Microsoft 365 Developer Program FAQ](https://learn.microsoft.com/en-us/office/developer-program/microsoft-365-developer-program-faq)。
  可行替代是自建租户，其自带域名即工作账号。
- **因此试用必须在切片可搬之后才开。** 在没有可搬产物时开启，60 天会消耗在熟悉界面上，
  而界面熟悉不是本项目要证明的能力。这条写进 roadmap 是因为它是时序陷阱：一年后重读文档
  的人看不出"提前开"的代价。

**它不进入更早的阶段。** 托管平台的学习密度低于自建阶段，因为它替使用者做掉了决策；把它
前移会用平台默认值替换掉本项目正在论证的取舍，与 Phase 0 的 probe 例外第 2 条同一条理由。

## 当前依赖

主 BO 是所有后续工作的上游。监管数据契约和验证规范可以并行研究，但 Gold schema、
生成器实现和展示层不得在 BO 未收敛时提前冻结。
