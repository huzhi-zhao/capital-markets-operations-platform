# Launch Records

Launch record 保存一次重要变更**实际上线或执行**时产生的证据：实际步骤、与设计的偏差、
验收结果、回滚条件和观察窗口。它不是每篇 requirement 或 design 的强制后继。

## 准入条件

出现以下任一情况时建立 launch record：

- 大规模生成、回填、数据迁移、历史重述或不可轻易重建的执行。
- 涉及 git 之外的环境、凭证、服务、调度或外部副作用。
- 需要明确的分阶段门禁、回滚或 roll-forward 方案。
- 关键数字或证据只在实际执行时产生，事后无法可靠补写。
- 上线后必须在明确时间窗口内观察指标或数据质量。

普通可逆部署由 PR、CI 和自动化测试记录即可。可重复执行的当前操作步骤属于
[guide](../../guide/README.md)，不能把历史 launch record 当成 runbook。

## 内容与生命周期

每篇至少包含：关联 design、执行日期与结果、关键时间线、实际偏差、验收实测、回滚或
遗留项、观察指标。保留可重跑命令和关键数字，不粘贴完整终端输出。

执行完成后正文冻结。后来的实测推翻数字或归因时追加带日期的更正，不改写原始记录。
文件名使用 `YYYY-MM-DD-kebab-case-topic.md`。
