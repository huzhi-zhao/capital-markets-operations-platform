# Documentation

项目文档按受众和用途分开维护。这里是唯一的总入口，不在多个目录重复保存同一份事实。

| 目录 | 受众 | 语言 | 内容 |
|---|---|---|---|
| [guide/](guide/README.md) | 外部读者、使用者和运维者 | English | 平台是什么、如何运行、如何排障，以及当前有效的操作方法 |
| [dev/](dev/README.md) | 开发者与架构评审者 | 中文为主，文件名使用 English kebab-case | 需求、架构、决策、变更设计、上线记录、事故复盘与协作约定 |
| [images/](images/README.md) | 所有文档作者 | 与引用它的文档一致 | 架构图、数据流图和其他文档资源 |

仓库根目录的 [README.md](../README.md) 是项目入口；本页负责把读者路由到正确的
文档体系。`guide/` 描述当前平台怎样使用，`dev/` 解释为什么这样设计，两者不混写。

`guide/` **只保存面向项目外部读者和实际操作者的公开操作文档**。即使某份材料能帮助
新开发者理解项目，只要它讨论 BO 收敛、内部路线、架构评估、技术选型、ADR 证据、
开工门禁或当前研发就绪度，就属于 `dev/`，不能因为带有“指导”性质而放入 `guide/`。
外部读者无需了解的规划状态和决策过程也不得出现在 `guide/`。

## 与个人笔记的边界

项目文档不是作者的全部书面产出。与本仓库并行存在一份**私人笔记**：ToucanShelf 知识库
的本地检出，位于仓库根的 `toucan-notes/`，有自己的 git 仓库，被本仓库 gitignore，
**不属于本仓库、不会被发布**。

分工一句话：**`docs/` 放结论与约束，笔记放素材与过程。** 由此得出三条：

- **一个事实只有一个家。** 决定一旦冻结就从笔记搬进 `docs/`，笔记只留指针和作者自己
  的理由。同一段口径、数字或结论不在两边各维护一份。
- **链接是单向的。** 笔记可以引用本仓库的文件路径；本仓库的任何文档**不引用笔记**，
  也不把笔记里的结论当作依据。这是上一节那条公开性要求的直接推论。
- **判断不清时先不写。**

完整的边界表、内容路由规则和 memogit 操作规矩见
[ToucanShelf 协作约定](dev/collaboration.md)。**本页不维护笔记的目录清单**，
那由笔记自己的 README 负责。

## 索引与引用规则

- 每个 Markdown 文件都必须在它的**直接父级索引**中登记。目录索引统一使用
  `README.md`；仓库根 `README.md` 登记本页。
- 一篇文档只有一个规范父级索引，但可以被任意数量的相关文档交叉引用。
  “登记一次”不是“只能被引用一次”。
- 新增、移动或重命名文档时，必须在同一次变更中更新父级索引和受影响的链接。
- 每张图片必须至少被一篇 Markdown 文档引用。无引用资源不进入 `images/`。
- 文档之间只链接，不复制定义、口径、命令或数字。需要从不同视角解释时，链接到
  唯一事实源，再补充本视角特有的内容。

## 写作边界

- 目录名使用语义名称，不使用数字前缀；数字编号只用于 ADR。
- 文件名一律使用 English kebab-case，正文语言不体现在路径中。
- 项目文档只保存对理解、实现或运营本系统有长期价值的内容。当前跨会话任务队列进入
  仓库根 [TODO](../TODO.md)；更细的临时进度、催办、逐文件改动清单和代码行讨论分别
  属于 issue、项目管理工具、PR、commit 和 code review。
- 本仓库是可独立阅读的公开项目。公开文档不得引用读者无法访问的私人笔记、对话、
  本地附件路径或未公开材料。外部事实必须给出可公开复核的来源。
- 宁可合并相关内容，也不为预计中的内容提前建立空目录。目录只在某类文档确定会增长、
  且已有清晰正面定义时建立。
